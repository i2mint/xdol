xdol.access#

Persisted, mergeable per-key access statistics for any store.

An AccessLog is an append-only JSONL file of access events, folded into an in-memory {key: AccessStats} on open; the log itself is a read-only Mapping of key to (immutable) AccessStats. track_access() wraps any MutableMapping so reads, writes and deletes are recorded. The log is the tracker of xdol.tiering.TieredStore.

Filesystem atime cannot do this job (under relatime it is never a count, and any backup pass resets it), hence an explicit log.

Event schema, one JSON object per line (plain string keys, so a filesystem tracer that only knows paths can append to the same file):

{"k": key, "op": "read"|"write"|"delete"|"admit"|"release"|"pin"|"unpin",
 "n": bytes, "from": "hot"|"cold"|null, "ts": unix_seconds, "tag": str|null}

Only k and op are required: an event without n leaves the size alone. Replay does not trust file order (several writers may append to one file): it parses every line (a torn or ill-typed one, e.g. a NaN ts or a string n, is skipped), applies the snapshot lines first, then folds the other events in (ts, line number) order, exactly as live recording folds them. So a delete clears a key (pin included) and only later-stamped events bring it back. An event without ts is ordered right after the line before it in the file (it takes that line’s timestamp, 0 at the top of the file): an unstamped delete still deletes what came before.

Keys must be JSON scalars, in practice str: a key that does not survive a JSON round trip (a tuple, a Path…) is counted in memory but lost or changed on reopen, and recording one warns once.

A compacted file holds {"k": key, "op": "snapshot", "stats": {...}} lines, folded as initial state (the baseline the events after it build on).

>>> log = AccessLog()
>>> store = track_access({'a': b'xyz'}, tracker=log)
>>> store['a']
b'xyz'
>>> log['a'].reads
1
>>> 'a' in store  # membership is never recorded
True
>>> log['a'].frequency
1

class xdol.access.AccessLog(path=None, *, clock=<built-in function time>, tag=None, compact_above=None)[source]#

Bases: Mapping

Append-only JSONL access log, readable as a Mapping of key -> AccessStats.

Parameters:

  • path (str | PathLike | None) – log file; None keeps everything in memory (tests).

  • clock (Callable[[], float]) – callable returning unix seconds.

  • tag (str | None) – label stamped on each event; defaults to platform.node().

  • compact_above (int | None) – when opening finds more than this many events (lines other than snapshots) in the file, compact() it (None: never; the file then grows with every access). Same caveat as compact(): only for a log with a single writer.

Opening replays the file in timestamp order (see the module docstring), so the stats equal what recording those events live would give. Replay streams in constant memory when the file is already in that order (the normal case for one writer) and buffers it only when timestamps go back: a log several writers append to is out of order, so opening it still costs memory proportional to its length. A tracker never raises into a store’s read path: if the file cannot be written, a warning is issued once and counting continues in memory. Not thread-safe.

xdol.access.track_access(store, *, tracker=None, clock=None, tag=None)[source]#

Wrap store so reads, writes and deletes are recorded in tracker.

__contains__, __iter__ and __len__ are never recorded. Without a tracker, default_access_log_for() picks one, built with clock and tag (passing either alongside a tracker is an error: set them on the log). A value without len is recorded with size 0. The wrapped store is available as .store and the log as .tracker.

Return type:

MutableMapping
