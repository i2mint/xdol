xdol.updating#

Controlled updates of one mapping from another, with customizable policies.

update_with_policy decides, key by key, whether to copy a source item into a target mapping. It goes beyond dict.update() with:

  • built-in policies (always update, update if different, prefer target, prefer source)

  • custom decision functions and custom “key info” extractors (compare sizes, hashes or timestamps instead of reading values)

  • statistics about what was examined, updated, added, unchanged or deleted

  • specialized entry points (content-hash comparison, timestamps, local files)

A last section names the operations on a master / copy pair (companions of xdol.tiering): backfill (push to master what only the copy has), reconcile (update the copy from master) and verify (compare without writing).

Custom update logic with a hash function:

>>> target = {"a": "hello", "b": "world"}
>>> source = {"a": "hello!", "c": "python"}
>>> update_by_content_hash(target, source, hash_function=lambda x: len(x))
{'examined': 2, 'updated': 1, 'added': 1, 'unchanged': 0, 'deleted': 0}
>>> target
{'a': 'hello!', 'b': 'world', 'c': 'python'}

Using convenience methods:

>>> update_with_policy.missing_only(target, source)
{'examined': 2, 'updated': 0, 'added': 0, 'unchanged': 2, 'deleted': 0}
>>> target
{'a': 'hello!', 'b': 'world', 'c': 'python'}

xdol.updating.backfill(copy, master, *, keys_to_consider=<function _just_source_keys>)[source]#

Push to master the items that only copy has. Never overwrites.

Decisions use key presence only: the one value read is copy[k] for each key actually pushed, so nothing is ever downloaded from a cold (e.g. S3) master.

>>> master, copy = {'a': 1}, {'a': 9, 'b': 2}
>>> backfill(copy, master).added
1
>>> master
{'a': 1, 'b': 2}
Return type:

UpdateStats

xdol.updating.content_hash_key_info(store, key)[source]#

Default key_info for verify().

Text and bytes-like values give a sha256 of their content, tagged by kind so that 'a' and b'a' differ. Any other value is returned as is, so verify() compares it with == (1 == 1.0, dict order ignored).

>>> h = lambda v: content_hash_key_info({'k': v}, 'k')
>>> h(b'a') == h(bytearray(b'a')), h(b'a') == h('a')
(True, False)
>>> h({'x': 1})
{'x': 1}
Return type:

Any

  • policy (DefaultPolicy | UpdateDecider) – Either a DefaultPolicy enum value or a custom decision function

  • target_key_info (KeyInfoExtractor | None) – Function to extract comparison info from target keys

  • source_key_info (KeyInfoExtractor | None) – Function to extract comparison info from source keys

  • keys_to_consider (Union[Iterable[K], Callable[[Mapping, MutableMapping], Iterable[K]]]) – Specific iterable of keys to consider or a callable to make this from source and target. The default will consider source keys only.

  • verbose (bool | Callable[[K, KeyDecision], Any]) – If True, will print debug information, if callable, call with (key, decision) on each key that is looped over

dict[str, int]

Dictionary with statistics about the update operation

Examples

>>> target = {"a": 1, "b": 2}
>>> source = {"a": 10, "c": 30}
>>> update_with_policy(target, source)
{'examined': 2, 'updated': 1, 'added': 1, 'unchanged': 0, 'deleted': 0}
>>> target
{'a': 10, 'b': 2, 'c': 30}

>>> # Using PREFER_TARGET policy
>>> target = {"a": 1, "b": 2}
>>> source = {"a": 10, "c": 30}

>>> target
{'a': 1, 'b': 2, 'c': 30}
